Root actions are absent from Nix by design, but **NixOS can support them**. AppImage and Flatpak can also use a separately installed host helper; neither can provide automatic host elevation from its package alone. No files changed, builds run, or applications launched.

**Findings and root causes**

- The flake removes `elevation-helper` and creates `.root-actions-disabled`; it exports no NixOS module. Evidence: [flake.nix:63](flake.nix:63), [flake.nix:92](flake.nix:92).
- Disabling is broader than missing installation: marker, Flatpak runtime, AppImage variables, and `FILES_DISABLE_ROOT_ACTIONS=1` suppress **all** elevation, including terminals. Evidence: [RootActionsAvailability.cs:19](src/Files.Platform.Linux/Elevation/RootActionsAvailability.cs:19).
- Native elevation requires fixed helper/policy paths. Helper checks reject symlinks, non-root ownership, and group/other-writable ancestors; privilege tools are searched only under `/usr/bin` and `/bin`. Evidence: [ElevationHelperProtocol.cs:25](src/Files.Platform.Abstractions/Elevation/ElevationHelperProtocol.cs:25), [ElevationTrust.cs:138](src/Files.Platform.Linux/Elevation/ElevationTrust.cs:138), [ElevationTrust.cs:173](src/Files.Platform.Linux/Elevation/ElevationTrust.cs:173).
- Delete/Rename/Paste require an unprivileged `--root` launch **and** available elevation service. Ordinary launches expose only the independent root-terminal action. Evidence: [RootActionMode.cs:18](src/Files.Platform.Linux/Elevation/RootActionMode.cs:18), [RootActionsHelper.cs:23](src/Files.App/Helpers/RootActionsHelper.cs:23).
- The security boundary already binds the sanitized operation summary and SHA-256 to exact stdin JSON; the helper verifies both. Policy requires fresh `auth_admin`, denies inactive/other sessions, and names the executable. Preserve this across packages. Evidence: [HelperAuthorization.cs:38](src/Files.Platform.Linux/Elevation/HelperAuthorization.cs:38), [root-actions.policy:8](packaging/linux/io.github.memergamer.LinuxFiles.root-actions.policy:8).
- If “permissions” also means elevated chmod/chown: those are **not supported helper operations**. The existing permissions service uses current-process privileges. Evidence: [ElevationHelperProtocol.cs:63](src/Files.Platform.Abstractions/Elevation/ElevationHelperProtocol.cs:63), [LinuxFilePermissionsService.cs:62](src/Files.Platform.Linux/Permissions/LinuxFilePermissionsService.cs:62).

**Concrete per-package proposals**

- **AUR/pacman — S.** Installation support already exists: both recipes install helper mode 0755 and policy mode 0644 at the expected system paths. Polkit remains optional, so availability depends on its installation and an authentication agent. Keep this layout; document prerequisites or make polkit required if guaranteed functionality is intended. Evidence: [source PKGBUILD:41](packaging/linux/aur/linuxfiles/PKGBUILD:41), [binary PKGBUILD:43](packaging/linux/aur/linuxfiles-bin/PKGBUILD:43). Runtime success was not verified here.
- **Nix/NixOS — L.** Retain and ELF-patch the AOT helper; add `nixosModules.default` with an opt-in root-actions option. Enable `security.polkit`, install a generated action through a system package’s `share/polkit-1/actions`, and use `environment.etc` for a trusted deployment manifest identifying helper/policy paths. Use `security.wrappers` for **pkexec**, never setuid the helper. Current upstream separately exposes `enablePkexecWrapper`; check compatibility with the locked revision. [NixOS polkit module](https://raw.githubusercontent.com/NixOS/nixpkgs/nixos-unstable/nixos/modules/security/polkit.nix).
- **Nix trust changes — included in L.** Update `ElevationTrust.cs` to recognize `/run/wrappers/bin` and `/run/current-system/sw/bin`; prefer the privileged wrapper for pkexec/sudo. Validate every root-controlled symlink traversal and its resolved target. `/nix/store` can be root-owned mode **1775**, so current checks reject it: permit only a narrowly reviewed sticky-store exception with root-owned, non-writable store entries below it; reject user-owned stores. [Nix configuration reference](https://releases.nixos.org/nix/nix-2.35.0/manual/command-ref/conf-file.html).
- **Nix execution paths.** Replace fixed-path assumptions consistently in `PkexecElevationService.cs`, `ElevationPlanPreview.cs`, and deployment discovery; generate policy `exec.path` matching the exact invoked helper. Handle generation switches without falling back to a generic prompt. Merely installing via `nix profile` cannot activate host polkit integration. Main risks: trust exceptions, policy/path mismatch, loader dependencies, and upgrades.
- **Flatpak — L, requires host installation.** Today the manifest removes the helper, disables elevation, and deliberately omits host-spawn permission. Evidence: [manifest:35](packaging/linux/flatpak/io.github.memergamer.LinuxFiles.yml:35). A host-integration variant could grant `--talk-name=org.freedesktop.Flatpak` and use `flatpak-spawn --host` with a fixed host bridge/helper installation. Host spawning runs unsandboxed; this broad permission weakens sandbox isolation independently of root authentication. [Flatpak reference](https://docs.flatpak.org/en/latest/flatpak-command-reference.html).
- **Flatpak implementation.** Add host-side discovery/planning and literal argv/stdin forwarding; validate host paths before preview, rejecting sandbox-only paths and unsafe translations. Preserve digest binding, bounded results, and cancellation semantics. Sandbox filesystem checks cannot establish host helper trust. A Flatpak alone cannot install the host helper/action; `--filesystem=host` grants neither root privileges nor equivalent namespace visibility.
- **AppImage — M.** Replace blanket runtime/marker disabling with trusted host-helper availability, retaining explicit user disable controls. Supply a documented companion installer using the existing hardened installation flow. Extracted helpers must first be installed into root-owned system locations; invoking one directly from a user-controlled extraction directory fails the trust model. Current removal/disable points: [build-appimage.sh:57](packaging/linux/appimage/build-appimage.sh:57), [build-appimage.sh:77](packaging/linux/appimage/build-appimage.sh:77). Risks: helper/app version mismatch and administrator trust in installer/build output.
- **Tarball — S.** Already supports `install-local.sh --install-root-helper`, installing separately through sudo. Reuse its snapshot/hash checks and refusal to overwrite package-owned paths; document prerequisites, updates, and manual system-helper removal. Evidence: [install-local.sh:49](scripts/linux/install-local.sh:49), [install-root-helper.py:32](scripts/linux/install-root-helper.py:32).

**Verification and uncertainty**

Static inspection cannot prove menu visibility, `--root` window routing, preview/cancel behavior, packaged loader startup, or Flatpak host-path transport. Verify these only through [headless-run.sh:5](scripts/linux/headless-run.sh:5), using private Xvfb and throwaway HOME—never the real display.

The harness blocks the system bus, so it does **not** establish real polkit authentication or privileged-operation success ([headless-run.sh:101](scripts/linux/headless-run.sh:101)). Those require a disposable distro/NixOS VM with private Xvfb and controlled authentication. I could not verify the locked nixpkgs module source; exact option compatibility, store permissions, generation switching, and Flatpak transport remain unproven.
